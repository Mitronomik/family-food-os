2. 3. Explicitly pass only the **permitted test fixture resolver** through all relevant seed and composition creation points; regular runtime path remains unchanged. Confirm no production dependency, schema mutation, source rights change, global patch, or disabled FK enforcement. Tests must demonstrate normal default `uuid4` behavior is unchanged on an ordinary independent seed.
4. Capture original-code **actual composed PlannerRequest**, not merely its output, in a hermetic temp process at the pinned historical SHA, preserving source bundle/version hashes; capture a current candidate request in an identical independent environment. Compare **all** fields in §2 field-by-field after stable semantic normalization and flag unprovable items.
5. Only then attempt two independent full seed → **real unchanged** `PlannerService.generate_authoritative` → persisted/current readback, with exact historical 21 source-code/date/role, 42 six-place positive Decimal member values and archive-anchored `731ef32e…`. Source rights/Step changes/invalid nutrition or misleading same-count alternative weeks **fail closed**. **Risk:** routing a new resolver through the ordinary production seed/composer signatures, even with a default `None`/unchanged behavior, is an **architecture/API-contract change** for that context, not merely a local test fix. The owner must approve its exact scope, alternatives and negative tests in a **separate implementation contract amendment** before Codex modifies it. Do not quietly embed it in this research PR or the merged negative-evidence PR #254.

## 6. FACT / ASSUMPTION / PROPOSED DECISION / OPEN

**FACT:** The two real fresh runs in accepted PR #254 verify **NO_GO for the current ordinary unstabilized seed**, not Option A impossibility. Source/ordered Step-content parity is 51/51; selected weeks differ. The historical original has 51 current active versions but no complete PlannerRequest or all precursor UUIDs. Existing zero-argument `id_factory` is not wired across the nested seed composers; historical/candidate UUID tie-breaking is observed, but not a proved sole root cause. All authoritative calorie/Serving/source rights calculations remain backend-owned.

**ASSUMPTION:** A fully isolated, explicit typed test-only identity resolver plus historical input parity might reproduce the old randomly generated semantic week without changing Planner. **Neither feasibility nor outcome is demonstrated.**

**PROPOSED DECISION FOR OWNER:** **`NO_GO_TO_POSITIVE_OPTION_A_IMPLEMENTATION_FROM_CURRENT_EVIDENCE`**. Permit *read-only historical request reconstruction and proof*; do **not yet** approve passing new factory parameters through production composition or seed modules. If a minimal test-only design can be specified without changing production contracts, request a new bounded implementation PR with independent acceptance.
